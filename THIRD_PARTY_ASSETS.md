# Third-party visual assets

## Visual policy

RC IT Services uses real-world photography only for public website imagery. Generated AI artwork, synthetic people, decorative AI illustrations and random image-search downloads are not permitted for service, industry, careers, contact, education or corporate imagery.

The image registry is centralised in `public/js/site-config.js` so every visual can be audited, replaced and licensed without hunting through page markup.

Approved source platforms in the current build:

- Pexels — real photography; license: https://www.pexels.com/license/
- Unsplash — real photography; license: https://unsplash.com/license

## Image-selection standard

Each image must answer a page-specific question before it is approved:

1. **What real activity does the image show?** The subject must be recognisable without relying on alt text to explain an unrelated stock photograph.
2. **Why does that activity belong on this page?** Cyber security should look like real security work, cloud should show infrastructure/platform work, careers should show recruitment or professional collaboration, education should show real learning environments, and Contact should show genuine business/customer communication.
3. **Is the image different from the page's secondary editorial image?** Hero and body photography are intentionally separated.
4. **Is the same photograph already being used as a homepage tile?** Homepage editorial cards use separate imagery from their destination pages wherever practical.
5. **Can the asset be used commercially under the source licence?** Source and photo ID are recorded before production use.

## Image-repetition rule

A service or industry destination page must not repeat the same photograph in its hero and primary body/editorial section. Homepage capability and industry tiles also use dedicated editorial photography rather than automatically reusing the destination-page hero image.

Intentional reuse should be rare and restricted to genuine site-wide brand motifs or functional contexts where the exact same visual is part of a consistent identity. Page-specific photography should otherwise remain unique.

## Accessibility and presentation

- Alt text describes the visible professional activity and does not invent facts about the people shown.
- Cropping must preserve the subject at desktop, tablet and mobile breakpoints.
- Photography should not be used merely to fill empty layout space; the image should reinforce the adjacent proposition or content section.
- Decorative overlays must not reduce recognisability of the real scene.

## Production asset handling

Before final commercial launch, RC should either:

1. keep the approved Pexels/Unsplash assets with this source record; or
2. replace them with RC-owned/licensed commercial photography and self-host optimised WebP/AVIF derivatives.

Where external photography remains, the asset must continue to be reviewed for subject relevance, licensing, loading performance, responsive cropping and accessibility text before release.
